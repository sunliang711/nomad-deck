# Vault Unseal Key 离线紧急备份格式

本文说明 NomadDeck 导出的 Vault Unseal Key 离线紧急备份文件的格式与解密方法。该文件是控制面整体失效时人工解封 Vault 的唯一依据，应保存在与控制面宿主机隔离的介质上。

## 1. 获取方式

管理员在 Vault 集群的密钥托管页面二次验证当前密码后导出备份，并设置不少于 12 个字符的备份口令。导出时可选择只包含当前生效代际，或同时包含全部历史代际（已废弃的代际不导出）。文件扩展名为 `.ndvkb`，文件名包含集群名称、当前生效代际编号与导出时间。执行 Rekey 或快照恢复改变生效代际后，应重新导出。

## 2. 文件结构

文件为二进制格式，所有多字节整数均为大端序：

| 偏移 | 长度 | 内容 |
| :--- | :--- | :--- |
| 0 | 5 | 魔数，ASCII 字符 `NDVKB` |
| 5 | 1 | 格式版本，当前为 `1` |
| 6 | 4 | Argon2id 时间参数（迭代次数） |
| 10 | 4 | Argon2id 内存参数（单位 KiB） |
| 14 | 1 | Argon2id 并行度 |
| 15 | 1 | 盐长度 S |
| 16 | S | 盐 |
| 16+S | 12 | AES-256-GCM Nonce |
| 28+S | 其余 | AES-256-GCM 密文（含 16 字节认证标签） |

解密密钥由 Argon2id 以备份口令与盐派生，输出 32 字节。偏移 0 至 28+S 的文件头整体作为 AES-GCM 的附加认证数据，文件头任何字节被改动都会导致解密失败。默认参数为时间 3、内存 65536 KiB、并行度 4、盐 16 字节。

## 3. 载荷内容

解密得到 UTF-8 编码的 JSON 对象，字段如下：

| 字段 | 说明 |
| :--- | :--- |
| `format` | 固定为 `nomad-deck-vault-unseal-backup` |
| `cluster_id` / `cluster_name` | 集群标识与名称 |
| `created_at` | 导出时间（RFC 3339） |
| `active_generation` | 导出时生效的密钥代际编号 |
| `generations` | 代际列表，每项包含 `generation`（编号）、`state`（`active` 或 `retired` 等）、`key_shares`（分片总数）、`key_threshold`（解封阈值）与 `unseal_keys`（Base64 编码的密钥数组） |

恢复 Rekey 之前生成的 Raft 快照时，需要使用快照对应代际的密钥，因此历史代际的密钥同样有用。

## 4. 解密与人工解封

NomadDeck 程序内置离线子命令，不依赖运行中的服务、数据库或主密钥，可在任意机器上执行：

```text
nomad-deck offline-backup decrypt <备份文件>
```

在终端中执行时程序提示输入备份口令且不回显；在脚本中可附加 `--passphrase-stdin` 从标准输入读取口令。程序将集群名称、生效代际与导出时间输出到标准错误，将完整载荷以 JSON 输出到标准输出。口令错误或文件被改动时程序报错退出，不输出任何密钥。

取得密钥后，在装有 Vault 命令行工具的机器上对每台 Vault 节点执行 `vault operator unseal`，依次提交达到阈值数量的、与集群当前代际一致的密钥。解封完成后应尽快恢复控制面，并在控制面中核对密钥代际状态。

## 5. 安全要求

备份文件与备份口令应分开保管。任何持有文件与口令的人都可以解封对应的 Vault 集群，其安全等级与控制面宿主机相同。解密输出包含明文密钥，应只在受控的终端中查看，不得重定向到共享位置或留存在命令历史中。
