# Vault 与 Docker 页面验收修复

## 问题与原因

全新 Vault 集群缺少启用 KV 挂载和创建 Secret 的页面入口，无法通过管理台准备工作负载密钥。集群概要仅使用初始列表，初始化后手动刷新仍显示旧状态。未获取密封状态时显示为 Unsealed。Docker 安装和升级表单未提供下载代理选项，直连仓库失败时无法通过页面选择系统代理。

## 行为

管理员可以启用 KV v2 挂载，在指定路径创建 Secret，并使用 CAS 版本更新。保存后以 Vault 返回的版本为准。挂载操作受管理员权限限制，校验路径并记录不含密钥内容的审计信息。集群摘要随实时状态更新，未知密封状态显示为 Unknown。Docker 安装和升级可以选择系统代理。

## 验证

- Vault 真实服务回归：创建嵌套挂载、非法路径、重复挂载、Secret 创建与读取、CAS 冲突、版本与治理检查通过，race 测试耗时 14.149 秒。
- HTTP 回归：viewer 无权启用挂载，未初始化集群拒绝启用挂载，race 测试通过，耗时 1.922 秒。
- 相关静态检查、前端类型检查和打包通过。
- 远程 Web UI：三节点 Vault 初始化后显示 healthy；创建 secret 挂载与 apps/web Secret，读取后更新到 v2 成功。
- 远程 Web UI：Docker 直连失败的节点经系统代理重新安装 29.10.0 成功。

## 部署

控制面运行于 10.2.69.8，HTTPS 端口 8555。修复经过 Linux 编译并替换控制面容器镜像，持久化数据继续使用原目录。实际自更新不在本次验收范围内。
