# Nomad HCL 积木编排

## 编辑方式

在 Nomad Job 中心载入现有 Job 或编写 HCL 后，切换到“可视化编排”。左侧结构树展示文件、Job、Group、Task 及其属性和子块，右侧编辑所选元素。任务层级遵循 Job → Group → Task；一个 Job 可以包含多个 Group，一个 Group 可以包含多个 Task。

选择父元素后，从“可添加元素”列表加入属性或子块。列表区分单个块和可重复块：resources、config、env 等单个块已有定义后不可重复添加；template、service、artifact 等可重复块可以继续添加。每种块实际允许的父级、标签数量和重复次数以规则表为准。Group 和 Task 名称在各自父级内唯一。driver 是 Task 的属性，config 是由 driver 决定字段的子块。

可重复块支持复制，复制命名块时自动选择未占用的名称。上下箭头调整同级顺序，拖拽结构树元素可以移动到合法父级；同名冲突和自包含移动会被拒绝。删除影响所选元素及其子级。撤销、重做保留最近三十次文档快照。

字符串、数字、布尔值及字符串数组提供值输入，env 和 meta 等集合提供键值编辑。复杂值可以使用原生 HCL 表达式，包括变量、函数、对象和 heredoc。driver 切换后 config 的可选字段随之变化，原有字段保留，是否删除由用户决定。未知插件或新版本字段可以通过原生扩展或 HCL 编辑器维护。

## 源码与提交

可视化编辑保留原始表达式、注释、locals、variable 以及未知字段和子块。生成预览时使用 HCL 格式化，不保证空白排版逐字节不变。非法草稿仍可编辑和返回 HCL 模式，但不能从可视化模式执行 Validate、Plan 或保存模板。

切换模式和提交前会等待最新积木生成 HCL，防止使用尚未更新的预览。每次修改立即清除旧 Plan，过期的 Plan 请求不会恢复旧 Apply 入口。可视化提交保存完整 HCL 源码，重新载入时可继续恢复结构。

切换到 JSON 时通过 Nomad 解析 HCL。JSON 内容未改变就切回 HCL 或可视化时，恢复缓存的原始 HCL 和变量；JSON 已修改时，仅允许能够完整转换的定义进入 HCL。无法完整转换时保留 JSON 并说明原因。

## 规则来源与校验边界

内置字段和块规则依据 Nomad 1.11.2 官方 API 的 HCL 标签，以及 Docker、exec、raw_exec、Java、QEMU 驱动的任务配置规则整理，包含九十七种结构。参考来源为 HashiCorp Nomad 的 v1.11.2 源码中 api、drivers 目录和 jobspec2 的变量规则。网络块的单例限制、Job 标签及 map 块采用 HCL 解码规则补充。

结构检查覆盖 HCL 表达式语法、单例、重复名称、标签数量、基本父子关系和必填属性。属性形式的集合与同名块不能同时定义。规则表允许保留未知扩展，不能替代集群版本和驱动的语义校验。部署前仍须执行 Nomad Validate、Plan 并检查结果，再确认 Apply。

文档最多 1 MiB、五千个元素和三十二层嵌套。可视化源码接口沿用 Job 操作的管理员权限。不新增数据库表、配置项或依赖。
