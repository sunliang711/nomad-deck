# systemd 启动限流与版本交接修复

## 故障与根因

10.2.92.59 的 NomadDeck 服务在 2026-11-25 21:13:53 正常停止后无法再次启动，systemd 报 start-limit-hit。此前服务多次正常启动，没有应用启动异常。标准单元设置十分钟最多两次启动，systemd 会把正常启动、手工重启和更新重启一起计入；累计正常操作后也会拒绝启动。

此外，退出码 75 用于更新后的版本交接，原配置只通过 RestartForceExitStatus 请求重启，没有把该退出码标记为成功。systemd 因此同时触发 OnFailure，21:13:26 的日志显示曾执行自动回退。

## 修复

标准部署单元及安装脚本内嵌单元增加 SuccessExitStatus=75，继续保留 RestartForceExitStatus=75。Type=notify 收到 READY 后执行 ExecStartPost 重置失败状态和启动计数，因此成功启动不会累计到下次正常重启；就绪前连续失败仍保留原有两次、十分钟的限流和 OnFailure 机制。

安装脚本在安装启动前清除旧失败状态，新增 --repair-service：完成环境、路径及现有程序和配置检查后，写入标准服务及回退单元、重新加载 systemd 并重启。该入口无需下载和替换应用，不修改配置、数据库、主密钥或版本软链；已有额外 drop-in 保留。

更新安装说明与设计说明，新增独立 systemd 集成回归脚本。无 Go 业务代码、数据库或依赖变更。

## 验证与恢复

bash 语法检查、ShellCheck 和差异检查通过。远程独立临时服务基于仓库实际单元创建，验证安装脚本内嵌单元一致、四次连续正常启动、退出码 75 自动重启且不触发 OnFailure、就绪前连续失败限流及失败通知。测试退出时清理专属临时单元。

通过上传后的项目 install.sh --repair-service 恢复 10.2.92.59；未使用手工编辑远程单元或单独执行 reset-failed 绕过问题。21:20:21 服务恢复 active/running，实际程序仍为 v0.0.5 (7d99a08)。使用本机自签名证书验证 HTTPS，/readyz 返回 ready；Tabbit 页面验证登录表单正常显示。

本次没有执行真实自更新发布或恢复业务数据库。版本交接及失败触发行为通过独立模拟进程验证，现有自动回退业务逻辑保持不变。
